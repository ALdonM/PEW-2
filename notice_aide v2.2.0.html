Notice Théorique, Guide d'Utilisation & Documentation Technique — Soliton ATPEW (v2.2.0)

1 — Partie Théorique

1-1 La géométrie associée aux hypothèses ($V_{\text{total}} = \pi + \pi^2 + 4\pi^3$)

Le modèle repose sur une hypothèse géométrique fondamentale : la constante de structure fine de l'électrodynamique, $\alpha^{-1} \approx 137,036$, représente la somme des volumes invariants engendrés par une structure spatio-temporelle à trois étages sur une durée cyclique globale de $4\pi T$ (soit deux tours complets nécessaires pour qu'un fermion de Spin 1/2 retrouve son état de phase initial) :

$$V_{\text{total}} = V_1 + V_2 + V_3 = V_{\text{sphère}} + V_{\text{tore}} + V_{\text{hélice}} = \pi + \pi^2 + 4\pi^3 \approx 137,03630378$$

Explication du pourquoi des hypothèses retenues et calcul des valeurs obtenues :

  • Sphère centrale ($V_1 = \pi$) : Évaluée sur la durée $4\pi T$. La symétrie sphérique parfaite fait que l'extension temporelle n'ajoute aucun degré de liberté volumique. Le volume d'enveloppe fixe le rayon : $$V_1 = \frac{4}{3}\pi R_{\text{sphère}}^3 = \pi \implies R_{\text{sphère}} = \left(\frac{3}{4}\right)^{1/3} \approx 0,90856 \text{ u}$$
  • Tore support ($V_2 = \pi^2$) : Évalué sur $4\pi T$. Le tore possède une symétrie par rotation axiale. La projection volumique fixe l'invariant : $$V_2 = 2\pi^2 R_{\text{tore}} r_{\text{tube}}^2 = \pi^2 \implies 2 R_{\text{tore}} r_{\text{tube}}^2 = 1$$ Sous la contrainte d'adjonction géométrique $R_{\text{tore}} = R_{\text{sphère}} + r_{\text{tube}}$, le rayon du tube est la racine réelle de l'équation cubique $2 r_{\text{tube}}^3 + 2 R_{\text{sphère}} r_{\text{tube}}^2 - 1 = 0$, ce qui donne : $$r_{\text{tube}} \approx 0,57962 \text{ u} \quad \text{et} \quad R_{\text{tore}} \approx 1,48818 \text{ u}$$
  • Hélice secondaire ($V_3 = 4\pi^3$) : L'hélice ne possédant pas de symétrie axiale, le balayage temporel sur le cycle spinoriel $4\pi T$ génère le volume complet. L'action géométrique s'écrit $V_3 = \pi (r_h^{(0)})^2 L_{\text{hélice}} = 4\pi^3$, d'où le rayon nu : $$r_h^{(0)} = \frac{2\pi}{\sqrt{L_{\text{hélice}}}}$$
  • Démonstration de la valeur $r_{\text{hélice}} = 0,5592 \text{ u}$ :
    Le volume d'action par demi-tour ($2\pi$) vaut $V_{\text{inst}} = \frac{V_3}{4\pi} = \pi^2 \approx 9,8696 \text{ u}^3$. Pour la longueur déroulée du brin $(1, 1, 32)$ calculée à $L_{\text{hélice}} \approx 109,3277 \text{ u}$, l'égalité $V_{\text{inst}} = \pi r_{\text{hélice}}^2 \cdot L_{\text{normalisé}}$ impose $r_{\text{hélice}} \approx 0,5592 \text{ u}$. Cette valeur est donc un résultat géométrique déduit et verrouillé, non ajusté ad-hoc.
  • Contrainte de fermeture topologique $C^0, C^1, C^2$ : Pour former un soliton stable sans saut de tangente ni pincement de courbure, les enroulements $(n_T, n_P, n_H)$ doivent vérifier la condition de lissure. Le triplet minimal verrouillé de manière unique est $(n_T=1, n_P=1, n_H=32)$.

1-2 Le Modèle physique supposé (Les liens avec ATPEW / Onde Mère)

Dans la Théorie de l'Onde Mère (Primordial Energy Wave), la matière est constituée de nœuds de vibration non-linéaires auto-confinés :

  • Charge Électrique ($Q = -1.000 e$) : Émerge géométriquement comme l'invariant topologique de Hopf ($Q = \frac{n_T \cdot n_P \cdot n_H}{32} = 1$). La charge est une propriété géométrique globale de verrouillage $3\text{D}$.
  • Champ Électrique Radial ($\mathbf{E}_{\text{rad}}$) : Émerge de la rigidité élastique du milieu sous gradient de phase. Il obéit strictement à la loi de Gauss : $\oint \mathbf{E} \cdot d\mathbf{A} = \frac{Q}{\varepsilon_0}$.
  • Quantum d'Action ($h$) : Représente l'action totale accumulée par l'onde lors de son bouclage spinoriel complet sur $4\pi$ ($h = E \cdot T_{4\pi}$).
  • Zitterbewegung (ZBW) & Compton : L'oscillation ultra-rapide émerge de la vitesse de phase circulant le long du brin $H_2=32$. La longueur déroulée correspond à la longueur d'onde de Compton $\lambda_c = \frac{h}{m_e c} \approx 2,426 \text{ pm}$, induisant un rayon de Compton réduit $r_c \approx 386,16 \text{ fm}$.
  • Isospin Faible $SU(2)_L \times U(1)_Y$ & Chiralité : La respiration radiale du tube fait osciller la projection du brin entre une configuration allongée gauchère ($e_L$, $T_3 = -1/2$, couplée au champ faible) et une configuration élargie droitière ($e_R$, $T_3 = 0$).
  • Formule Théorique Dynamique de $\alpha_{\text{em}}^{-1}$ (Couche A v2.1.1) :
    En intégrant les fluctuations quantiques du vide et la vibration ZBW du tube support ($\sigma_{\text{ZBW}}, \sigma_{\text{vide}}$), le volume effectif $\langle V_3 \rangle$ est réévalué dynamiquement : $$\alpha_{\text{em}}^{-1} = V_1 + V_2 + \langle V_3 \rangle = \pi + \pi^2 + 4\pi^3 \cdot \overline{A^2} \left( 1 + \frac{\sigma_{\text{ZBW}}^2 + \sigma_{\text{vide}}^2}{(r_h^{(0)})^2} \right)$$ Cette relation comble l'écart de $2,2 \text{ ppm}$ entre la géométrie statique ($137,0363$) et la valeur CODATA ($137,035999177$).

3 — Partie Codage et Structure du Code

3-1 Structure du Code et Choix Techniques

Le code est conçu de manière autoportante sans dépendance lourde, s'appuyant sur Three.js (r128) et OrbitControls.js. Il s'articule autour des composants majeurs suivants :

  • Objet d'État Central (params) : Centralise l'intégralité des variables de saisie. Chaque modification dans l'interface UI met à jour cet objet.
  • Moteur Géométrique Paramétrique :
    • getHelixCenterPoint(t) : Calcule la trajectoire du cœur sur le tore support en intégrant la respiration et l'enveloppe.
    • getDoubleHelixPoint(t, wavePhase) : Érige un repère mobile local de Frenet $(T, E_1, E_2)$ pour projeter l'hélice $H_2=32$ dans l'espace 3D.
  • Boucle d'Animation Temps Réel (animateWave() à 60 FPS) :
    • Recalcule les 800 nœuds du brin 3D.
    • Effectue l'intégration numérique discrète de la longueur d'arc $L_{\text{hélice}} = \sum \|P_i - P_{i-1}\|$.
    • Calcule le courant efficace formel $I_{\text{eff}} = \frac{e \cdot c}{L_{\text{hélice}}}$.
    • Exécute l'algorithme de détection d'interférences $O(N^2)$ pour colorer les nœuds en rouge sous le seuil critique.
    • Met à jour les attributs de géométrie WebGL (posAttr.needsUpdate = true) sans réallocation mémoire GPU.

Procédure de fonctionnement de concert sur GitHub / GitHub Pages :

  1. Placer le fichier principal de la simulation (ex: PEW Simulation Soliton 3D - v2.2.0.html) et le présent fichier d'aide (notice_aide v2.2.0.html) dans la racine du même dépôt GitHub.
  2. Dans le code de la simulation, le bouton d'aide effectue l'appel URL-encodé : 
    document.getElementById('btn-help').addEventListener('click', () => {
    window.open(encodeURIComponent('notice_aide v2.2.0.html'), '_blank');

  3. Activer GitHub Pages dans les paramètres du dépôt (Settings > Pages > Branch: main / root). Les deux fichiers fonctionneront parfaitement ensemble sans erreur CORS.
